===========================================
2. WHY REDIS?
===========================================

Redis ek in-memory database hai.

In-memory matlab:
Data RAM me store hota hai.

RAM bahut fast hoti hai.

Isliye Redis extremely fast hai.

Normal database:
Disk based -> slower

Redis:
RAM based -> ultra fast


===========================================
3. WHY NOT MONGODB FOR OTP?
===========================================

OTP temporary hota hai.

30 sec ya 60 sec baad useless ho jata hai.

Agar MongoDB use karenge:
- disk write hoga
- unnecessary storage
- cleanup karna padega

Redis me:
- auto expire
- super fast
- perfect for temporary data

Isi liye companies Redis use karti hain.


===========================================
4. BIG SCALE ARCHITECTURE
===========================================

Real-world flow:

User App
   |
   v
Backend Server (Node.js)
   |
   v
Redis Store
   |
   v
SMS Provider

Step-by-step:

1. User phone number enter karta hai
2. Backend OTP generate karta hai
3. Redis me save karta hai
4. SMS service OTP bhejti hai
5. User OTP enter karta hai
6. Backend Redis se compare karta hai
7. Match hua -> login success


===========================================
5. WHY TTL IMPORTANT?
===========================================

TTL = Time To Live

OTP forever valid nahi hona chahiye.

Security issue ho jayega.

Example:
Agar OTP 5 din valid raha
to hacker misuse kar sakta hai.

TTL solve karta hai:
- automatic expiry
- automatic cleanup
- better security


===========================================
6. WHAT IS HAPPENING IN CODE?
===========================================

STEP 1:
Express server create hua

STEP 2:
Redis connection establish hua

STEP 3:
Phone number ke liye unique key banayi

Example:
otp:9876543210

STEP 4:
Random OTP generate hua

STEP 5:
Redis me store hua with expiry

SET otp:9876543210 123456 EX 30

STEP 6:
Verification request aayi

STEP 7:
Redis se OTP nikala

STEP 8:
Compare kiya

STEP 9:
Success -> OTP delete


===========================================
7. WHY DELETE OTP AFTER VERIFY?
===========================================

Security.

Agar delete nahi karenge:
same OTP dobara use ho sakta hai.

Isliye successful verification ke baad:
DEL otp:9876543210


===========================================
8. WHY ASYNC AWAIT?
===========================================

Redis operations asynchronous hote hain.

Network/database time leta hai.

Agar await nahi use karenge:
code wrong order me run ho sakta hai.

await ensure karta hai:
"pehle Redis ka kaam complete karo"
